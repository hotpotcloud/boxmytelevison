# 001：账号、持久登录与 UI 调整

## 用户目标

用户注册自己的账号并登录后，可以直接使用搜索、点播、直播，不用反复输入站点访问密码。刷新页面、重启应用和正常代码发布后，未过期的账号会话仍有效。

## 范围与默认值

1. 普通用户以邮箱注册和登录，保存邮箱与注册时间；邮箱按小写去重。管理员使用独立登录名。
2. 密码：8–128 字符，不进行 trim，不影响空格和特殊字符。
3. 注册方式：邮箱 + 密码直接注册，可配置关闭注册；不需要邀请码，不发送验证码，不声称验证邮箱归属。
4. 登录表单默认“保持登录”，90 天固定到期；取消后为浏览器会话，服务端最多 24 小时。浏览器会话恢复机制可能恢复会话 Cookie，不承诺关闭窗口必然退出。
5. 可退出当前设备、修改密码；改密要求旧密码正确，并使所有设备重新登录。
6. 沿用访问密码入口作为兼容入口，不自动把访客升级成注册用户。
7. UI 调整范围：整体布局与交互重做，iOS/macOS 风格、分组导航、真实分页、移动端底部导航；先评审设计稿再实现。包括首页信息层级、导航账号入口、登录注册弹窗、账号页面，保留亮暗主题与原有播放能力。
8. 观看记录、收藏、源配置暂不进行服务端同步，也不承诺账号之间自动隔离现有本机历史。

## 验收

- AC-01：合法账号可注册，大小写重复邮箱被拒绝；注册关闭时不能注册。
- AC-02：正确账号密码可登录，错误密码得到统一错误，不泄露账号存在与否；未登录不能调用受保护 API。
- AC-03：账号登录后，不再要求访问密码；服务重启后会话继续有效。
- AC-04：退出后复制旧 Cookie 无法恢复账号会话；修改密码后全部旧会话失效。
- AC-05：数据库、数据库备份和会话令牌不进入 Git、静态目录或公开构建产物。
- AC-06：代码发布使用固定数据库路径，保留用户、会话和迁移记录；部署前执行一致性备份。
- AC-07：登录注册表单支持键盘、自动填充、明确的错误提示、提交中状态；375px 屏幕不横向溢出。
- AC-08：原有访问密码、点播和直播鉴权回归通过。
- AC-09：记录本地测试、构建、部署和公网验证结果，区分未验证事项。
